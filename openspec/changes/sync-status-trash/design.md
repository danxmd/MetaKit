# Design

- **Status.** The session exposes `status`: `{ pending, lastFlushAt, lastRemote: { by, at } | null, error }`. The UI line says "Saved", "Saving…", "Last change from <name>, <n> s ago" (name from presence, else the instance id) or the error. The age text updates every second.
- **Clash notice.** The session reports `clash: { path, mine, theirs, by }` when a remote line overwrites a register this session wrote after the remote file's `seen` for this instance. The UI shows a dismissable notice naming the field in plain English ("Anna changed Priority at the same time; her value was kept").
- **Trash.** Models already have trash markers (phase 2). Tool libraries get the same (`trashTool`, `restoreTool`, `listTools({includeTrashed})`). A marker records `at`; an item trashed more than 30 days ago is listed as expired (not restorable from the list, and a cleaning pass may remove files that this instance wrote). Files written by other instances are never removed, so an expired item is hidden, not erased.
- **Folder health.** `checkFolderHealth(adapter)` reads a sample of files and reports: reads slower than 2 s (the folder may be online-only: "Files On-Demand" or "stream files"), files that fail to read, zero-byte files, change files or snapshots that stay without a final newline, and names that look like conflicted copies (`(1)`, `conflicted copy`, `~`, `.tmp`). It cannot see whether the sync client is running; the message says so and points to the test protocol.
- **Protocol.** `docs/phase-3-test-protocol.md` has the steps for two machines over OneDrive and a SharePoint library and a results table to fill in. Done-when for 3.4 is Danial's run.
