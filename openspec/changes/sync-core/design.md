# Design

- **State.** `SyncState` holds `registers` (path key to `{t, by, v | unset}`), and per entity a `birth` and a `death` stamp. `applyOps(state, ops)` takes the maximum per key; it is pure in the sense that the result does not depend on the order or repetition of ops (tested with property tests of random concurrent edits, random delivery order and duplicates).
- **Document from state.** `materialize(kind, state)` builds the JSON document: alive entities with their registers, plain registers, connectors with a dead end left out. The session keeps the store's state and the sync state equal; a test checks `materialize(state)` against `store.state` after every step.
- **Local edits to ops.** `patchesToOps(kind, patches, clock)` turns the store's patches into lines: a patch at an entity path creates (birth plus every leaf) or deletes (death); a patch below writes the leaves that changed and unsets the ones that vanished. A drag or resize is one command, so it is already one batch of patches written at release.
- **Remote ops to the store.** `SyncState.apply` reports which entities and plain registers changed; the session rebuilds only those from the registers and calls `store.applyRemote(patches)` with entity-level patches, so the canvas scene follows with the code it already has.
- **Session.** `SyncSession` owns the clock, the pending lines and the sequence. It flushes after at most two seconds (a timer started by the first unflushed edit) and on close, reads other instances' new files when told (`rescan()`), and writes the snapshot on a timer (every few minutes) and on close, then removes its own folded change files. File reading follows the partial-file rule.
- **Seen.** The header of every change file records the last sequence read from every other instance. When a remote line overwrites a register that this session wrote after that remote file's `seen` for this instance, the session reports a clash (used by the notice in phase 3.4).
- **Undo among people.** `Store.undo` and `redo` check each patch of the step against the current value and skip the ones that no longer match, returning the number skipped.
- **Snapshots.** Version 2 as in ADR 0002. Opening reads snapshots first and then only the change files above their `seen`. Version 1 snapshots (a plain document) are read through a migration.
- **Year test.** Five simulated instances, a year of working days with edits, drags, deletes and undo, with snapshots every simulated hour of work and change files cleaned up as they would be; then a fresh instance loads the folder and the time is checked against the budget (1 second for the large model; the test uses a smaller number of edits per day but a model of 5,000 elements).
