# Design

- **Scene, not model.** The renderer reads a `Scene`: flat item records (id, kind, box, shape, label, connector route) built from a `Model` and `ToolLibrary`. `Scene` subscribes to store change events and updates only the items whose paths changed, so a drag or an attribute edit touches a few items.
- **Draw lists.** A draw list is a list of `Path2D` plus text runs for one element at its size. Its cache key is `shape | w | h | label | fill`; moving an element does not invalidate it because the list is in local coordinates and drawn with a translate. Connectors are polylines routed from the endpoints and bend points; their cache key is the point list.
- **Three layers** as in the spike: background (grid), scene bitmap (re-rendered when content or view settles, excluded items skipped while dragging), active layer (dragged items, their connectors, selection, handles, guides, rubber band). The overlay is a positioned `div` for text editing and tooltips.
- **Index.** One rbush over elements and connectors (connector boxes from their routes). Updated per changed item.
- **Level of detail.** Text under 4 px on screen and outlines of items under 2 px are skipped. Fine decorations (arrow heads) are skipped under 3 px line length.
- **Built-in shapes (temporary).** Until phase 4, `builtinShape(classDef)` picks rectangle, rounded rectangle, ellipse or diamond from a small name table (Event and Start/End are ellipses, Gateway a diamond, containers and swimlanes rectangles, everything else rounded); the table can be replaced through an option. Label is the first text attribute shown centred, wrapped to the box width.
- **Routing.** A connector with no bend points gets a three-segment orthogonal route between the facing edges; with bend points it follows them as given. Routes are computed on item change, not every frame, except for connectors of dragged elements, which use the same cheap function.
- **Benchmark.** The spike's scenarios run against the real engine on a model generated with the core types. CI compares draw work p95 and the share of frames over 20 ms with `bench/budget.json`, as the phase-0 report recommended. Interval p95 is reported only.
